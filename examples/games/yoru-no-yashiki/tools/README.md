# ローカル音声評価（近似・研究用）

必要環境: **Node.js 24.14.0 以上**（TypeScript の直接実行対応）。追加依存は不要。
リポジトリのルートから、外部のローカル JSON manifest を明示指定する。

```powershell
node examples/games/yoru-no-yashiki/tools/voice-eval.ts C:/private/voice-eval/manifest.json
```

既存のラベル付き音声だけを対象にする。録音や大声を要求しない。
音声・manifest の取得、録音、ネット接続、ファイル作成・削除・上書きはしない。
標準出力は全入力が成功したときだけのラベル別集計 JSON。
クリップ数、減点あり・なしの件数、減点あり率を出し、ゼロ件の率は `null`（未定義）。
パス、波形、個人情報、任意の入力文字列は出力しない。失敗は固定メッセージと終了コード 1。
入力はメモリに一時展開するが、保存・公開しない。出力先ファイル指定もない。

## Manifest と入力

次は形式の説明であり、音声素材・manifest ファイルは同梱しない。

```json
{
  "version": 1,
  "consentConfirmed": true,
  "usageRightsConfirmed": true,
  "validFrom": "2026-11-01T00:00:00.000Z",
  "expiresAt": "2026-12-01T00:00:00.000Z",
  "threshold": 0.1,
  "clips": [{ "path": "existing-clip.wav", "label": "scream" }]
}
```

両確認値は、**全クリップについて本人の同意・音声とラベルの利用権を確認済み**という実行者の申告。
ツール自体が同意・権利を証明するものではない。氏名、同意書、被験者 ID などは記入しない。
日時は上記の UTC・ミリ秒付き ISO 形式で必須。`validFrom <= 現在 < expiresAt` のみ受理する。
`expiresAt` は同意・利用許諾の有効期間と保持期間のうち最も早い期限とし、必要最短期間にする。
元音声、ラベル、同意記録の保持・アクセス制限・期限到来時の削除は管理者の責任。
ツールは期限外に失敗するだけで、入力を削除しない。
CLI は開始時だけでなく、manifest 読み込み後、各 WAV を開く直前・読み込み中・デコード前後、
分析フレームの境界、集計完了時と JSON 化後の標準出力直前に実時計を再確認する。
0 クリップでも再確認し、期限切れ・無効な時刻・観測した時計の逆行は固定エラーで終了し、部分集計を出さない。
試験用の `evaluateManifest(path, 数値now)` は指定時刻を固定して使い、実時計を参照しない。
これは境界ごとの検査であり、厳密な物理時刻の保証ではない。OS スケジューリングや時計の正しさ、
開く直前の検査から実際の I/O まで、および最終検査から出力までの競合は保証できない。
検出前に読み込み・解析が進む場合があり、メモリの即時消去・完全消去も保証しない。

manifest と WAV は checkout 外のローカル通常ファイルに置く（リンク解決後も確認）。
WAV パスは manifest 基準の相対パスまたは絶対パス。URL、UNC・デバイスパスは禁止。
ネットワークマウントやリモート転送される保存先も使用しないこと（OS のマウント元までは検出しない）。
未知の JSON フィールド、未知のラベル、同一実体パスの重複、不正 UTF-8 を拒否する。
ラベルは `scream` / `speech` / `noise` / `silence` のみ。`clips: []` も有効。
閾値は必須の有限数 `0.02`〜`0.5`。結果にも記録する（上記は `0.1`）。

上限は manifest 64 KiB・100 クリップ、WAV 4 MiB/件、20 ms〜10 秒/件、合計 60 秒。
WAV は little-endian RIFF/WAVE、PCM 形式 1、fmt 16 バイト、モノラル・符号付き PCM16、
整数サンプルレート 8,000〜192,000 Hz のみ。RIFF 長、チャンク境界・パディング、
重複 fmt/data、ブロックサイズ、バイトレート、空・奇数長データを検証する。
境界が正しい付加チャンクは読み飛ばす。ステレオ、float、拡張 fmt、圧縮、RF64 は非対応。
実行中は入力を変更しないこと。不正入力が途中にあっても成功集計を出さない。

## 解釈と限界

ゲーム本体の `VoiceGate` と `ScreamMeter` をそのまま呼ぶ。分類器・ゲームの挙動は変更しない。
分析窓は **8192 サンプル**、**固定 60 Hz・delta = 1/60 秒**。
時刻 `n/60` の末尾窓を取り、開始前はゼロ埋め。最初は `1/60`、クリップ末尾を超える窓は作らず、
1 フレーム未満の余りを捨てる。クリップごとに状態をリセットする。
既存 API 内部の間引き・最大 2048 サンプル分析・0.3 秒持続条件もそのままなので、
境界の結果はフレーム丸めと窓の履歴に依存する。ラベルは判定に渡さず集計にだけ使う。

現在の周期音近似では合成 440 Hz 単音も減点され得る。実声の悲鳴識別精度の根拠にはならない。
合成 440 Hz 音を 0.2 秒で切ると無減点でも、同じ音末に合成無音を 0.5 秒付けると、
窓内に音の履歴が残り、0.3 秒時点で減点される例がある。音末でのカット境界や無音追加も結果を変える。
これは固定 60 Hz・8192 サンプル窓による合成入力の例であり、実録音・人声や実環境の証拠ではない。
集計の母数は**クリップ数**で、フレーム数・人数ではない。ラベルごとの母数も必ず確認する。
同じ話者・セッション・元録音の切り出しが評価用と調整用の両方に跨がないよう分割し、重複を避け、
同意範囲内であらかじめサンプル分割とラベル基準を固定する。細切れで母数を水増ししない。
端末・マイク・ゲイン・距離・環境音・サンプルレートの差で結果は変わる。
ブラウザーの AnalyserNode の更新タイミング、リサンプリング、マイク処理、可変フレーム間隔、
実時間の中断・ネットワーク遅延・対戦状態は再現しない。**判定率 ≠ 商用品質**。

## 検証

既存の開発依存と Node.js 24 がある環境で実行する。テストは人工波形とメモリ上の模擬ファイルに加え、
OS 一時領域の一意な専用ディレクトリに合成 PCM16 WAV・manifest のみを作り、実 Node プロセスで CLI を検証する。
入力内容が不変であることを確認し、終了時は自分で作った専用ディレクトリだけを削除する。
実声・実マイク・外部データ・ネット接続は使わない。

```powershell
node node_modules/vitest/vitest.mjs run examples/games/yoru-no-yashiki/tests/voice-eval.test.ts --maxWorkers=1
node node_modules/prettier/bin/prettier.cjs --check examples/games/yoru-no-yashiki/tools/voice-eval.ts examples/games/yoru-no-yashiki/tools/README.md examples/games/yoru-no-yashiki/tests/voice-eval.test.ts
```
