- `MOQ_RELAY_EXECUTABLE_PATH`: `moq-relay 0.17.2` のWindows実行ファイル。ローカル候補は `.generated/yoru-relay-interop-ee484c4e633d4518ad9517c5e518c32d/moq-relay.exe`。
- `OPENSSL_EXECUTABLE_PATH`: OpenSSL実行ファイル。
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`: Google Chrome実行ファイル。

環境変数を設定したPowerShellからリポジトリルートで実行します。

```powershell
$env:MOQ_RELAY_EXECUTABLE_PATH = (Resolve-Path '.generated/yoru-relay-interop-ee484c4e633d4518ad9517c5e518c32d/moq-relay.exe').Path
$env:OPENSSL_EXECUTABLE_PATH = 'C:/Program Files/Git/usr/bin/openssl.exe'
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node node_modules/@playwright/test/cli.js test --config playwright.yoru-no-yashiki-real-moq.config.ts
```

上記のOpenSSL・ChromeのパスはこのWindows環境の例です。描画ありの独立シナリオだけを実行する場合は、同じ環境変数で次を実行します。`YORU_REAL_MOQ_RENDERER` 未指定時の既定値は `swiftshader` です。`swiftshader` と `hardware` 以外（空文字列を含む）は起動前に失敗します。既存の証拠を残す場合は未使用の出力ディレクトリを指定してください。再試行は0回です。

既定のCPU SwiftShaderモード（640×480 CSS px、DPR 0.5）:

```powershell
$env:YORU_REAL_MOQ_RENDERER = 'swiftshader'
node node_modules/@playwright/test/cli.js test --config playwright.yoru-no-yashiki-real-moq.config.ts --grep '描画あり:' --output .generated/yoru-no-yashiki-real-moq-swiftshader-results
```

実GPUモード（960×600 CSS px、DPR 1）を明示的に選ぶ場合:

```powershell
$env:YORU_REAL_MOQ_RENDERER = 'hardware'
node node_modules/@playwright/test/cli.js test --config playwright.yoru-no-yashiki-real-moq.config.ts --grep '描画あり:' --output .generated/yoru-no-yashiki-real-moq-hardware-results
Remove-Item Env:YORU_REAL_MOQ_RENDERER
```

両モードの証拠は別の出力先に隔離してください。Playwrightは実行時に指定出力先を消去するため、再実行で証拠を保持する場合はさらに別の未使用パスを指定します。実GPUモードだけ `--use-angle=swiftshader` を外し、通常のheadless ChromeのGPU選択を使います。GPU対応は端末・ドライバー・Chromeの実行環境に依存します。両画面の実WebGL renderer文字列を診断JSONと `rendering-evidence.json` に記録し、SwiftShader、llvmpipe、WARP等のソフトウェア・仮想描画は失敗にします。既知のGPU識別子を含まない不明rendererも失敗し、自動フォールバックを実GPUの成功として扱いません。両モードで同じ実MoQ・二画面・偽マイク・実描画・探索・暗転・時計・10秒超・接続・未中断・500ms検証を行い、合格基準は変えません。

試験ごとに実リレー、通常の `vite.config.yoru-no-yashiki.mjs`、独立したChrome 2プロセスと偽マイクを起動します。SDKのalias置換や製品プロトコルのモックは使いません。WebTransportは宛先の検証とready/closedの観測のみ行い、実装・ストリーム・送受信データは置換しません。HTTPは所有Viteだけ、WebTransportは所有リレーだけを許可し、WebSocket・service worker・ブラウザーの背景ネットワークを無効化し、外部DNS解決を遮断します。

実リレーは `--listen 127.0.0.1:<動的UDPポート> --listen-version moq-transport-14 --listen-tls-cert <一時証明書> --listen-tls-key <一時鍵> --auth-public anon/** --web-http-listen 127.0.0.1:0` で起動します。補助的な送信用UDPソケットも `--connect-bind 127.0.0.1:0` でlocalhostに制限し、`--cluster-lan=false --iroh-enabled=false` と環境変数の除去で外部探索・接続設定を無効化します。Viteも動的TCPポートの `127.0.0.1` のみです。55353/55354は使用せず、既存のプロセスやサーバーは再利用・停止しません。

自己署名証明書と鍵はOS一時ディレクトリ内の試験専用ディレクトリにだけ生成し、OS証明書ストアは変更しません。Chromeの `--ignore-certificate-errors-spki-list=<その一時証明書のSPKI>` と `--origin-to-force-quic-on=127.0.0.1:<所有ポート>` は試験中の独立プロセス限定です。証明書全般を無条件に無視するフラグは使用しません。通常のゲーム起動や外部接続には転用しないでください。

既存の2ケースは `HorrorWorld.render` を観測用関数に置換して描画を止め、接続、双方の準備、第一夜、手掛かりと暗転イベントの同期、実時間10.5秒の連続稼働、および相手Chrome終了による中断を検証します。

追加の「描画あり」ケースは元の `HorrorWorld.render` を毎フレーム実行し、独立した両Chromeの実WebTransport、Chromeの合成マイク、実WebGL描画を組み合わせます。既定のviewportは各640×480 CSS px、DPRは0.5、ANGLEのCPU SwiftShaderを使用します。明示的な実GPUモードのみ各960×600 CSS px、DPR 1になります。実描画バッファ寸法・GPU文字列も記録します。製品操作で接続、双方準備、第一夜、手掛かり探索、怪異暗転を進め、通常・暗転・回復時の両canvas PNGと画素の平均・標準偏差を保存し、暗転による減光と回復を比較します。

描画ありの観測は実時間10.5秒以上です。両画面それぞれで描画フレームの時間幅10秒以上、ゲーム内時計の10秒以上の進行、21フレーム以上、観測境界を含む最大描画間隔500ms未満、各フレームの実draw call・三角形数が正、WebGLコンテキスト未喪失、接続と第一夜の維持を必須とします。DOM状態遷移も保存し、一時的な中断や試験本体終了までの中断を見落とさないよう検査します。60fpsや高解像度の保証ではありません。時計、requestAnimationFrame、500msの安全中断、音声、製品peer、送受信は変更しません。

この試験は失敗を隠す再準備・自動再試行・期待失敗化や安全閾値の緩和を行いません。途中失敗した場合、それ以降の段階は未検証です。診断JSON（描画モード、PID、待受、実SDKパス、リレーログ、両画面状態、実WebTransport状態、描画統計・状態遷移）とブラウザートレースは既定で `.generated/yoru-no-yashiki-real-moq-results/` に残します。描画ありケースはPNGと `rendering-evidence.json` も保存します。成功・失敗とも所有ブラウザー、Vite、リレー、一時証明書だけを後片付けします。既存のhealth診断 `real-moq-health.json` も両描画モードで保存します。既定試験では実GPUを検証しません。実GPUモードでも実マイク、聞こえ方、WAN、30分・二夜の完走や高負荷での安定性は検証しません。 GPU識別子だけの事前確認やリレーURL未設定の接続失敗は、GPU対戦成功や製品不具合の証拠にはなりません。
