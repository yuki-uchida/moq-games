# PRの作成とマージ

ユーザーの明示的な指示、リポジトリの保護ルール、実行環境の制約を優先する。PR作成やマージを依頼されていない場合、このスキルだけを根拠に実行しない。

1. `git status`、現在のブランチ、リモートとPRのベースを確認し、無関係な変更を除外する。最新のベースを取得し、必要なら未公開の作業ブランチをrebaseする。公開済み履歴の書き換えやforce-pushは明示的な許可なしに行わない。コンフリクトは解消し、変更を再検証する。
2. 対象の差分を確認し、リポジトリが定めるチェックを実行してからコミット・pushする。失敗・未実行のチェックを成功扱いしない。
3. 正しいリポジトリとベースにPRを作成する。概要はリポジトリの記載規則に従い、現在の差分に合うよう簡潔に書く。
4. PRのHEADとコンフリクトを確認し、コンフリクトがあれば解消する。マージ前のCIやレビューは待たず、保護ルールは回避しない。
5. ユーザーの指示とリポジトリ設定が許す場合、スカッシュマージし、マージ完了とベース側のCIを確認する。失敗や未完了は報告し、成功と偽らない。

PRを作らない・マージしないとの指示がある場合はその時点で止める。認証、権限、保護ルール、利用できないチェックなどで進めない場合は状況と残作業を報告する。
