# /goal 運用ルール

`/goal` でゴールが有効な間はこの手順で進める。評価はまず自分が行い、自分が合格と判断したときだけ**別ベンダーのセカンドオピニオン**を求める。完了条件は両方の合格。サブエージェントの起動方法・報告形式は `subagent-start` スキルに従う（このスキルはユーザー指定なので、モデル選択は下記が優先）。

このスキルは Claude（`.claude/skills/`）と Codex（`.agents/skills/` のシンボリックリンク）の両方から読まれる。**自分が動いている側の表を使う。**

## 大きな変更の進め方

大きな変更プランは、各ステップが単独で動作し検証できる単位に分け、ステップごとに PR を作成する。各 PR を検証・マージしてから次の PR を進める。後続の変更がなければ動作しないステップは、必要な変更とまとめて、マージ時に動作する一つの PR にする。ユーザーが別の公開方法を明示した場合は、その指示を優先する。

## 役割

### 自分が Claude 側のとき

| 役割                     | モデル                                                                                                               | 推論レベル                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 自分（計画・評価・統合） | 現在のセッション                                                                                                     | —                                                                          |
| セカンドオピニオン       | 別ベンダーで自分と同格: GPT-6.1 Terra（T3 `delegate_task`, `providerInstanceId: "codex"`, `model: "gpt-6.1-terra"`） | 自分と同じレベル（`reasoningEffort`）。自分のレベルが分からなければ `high` |
| 実装者                   | 原則として同ベンダーの最下位モデル: Claude Sonnet（Agent ツール `model: "sonnet"`, `run_in_background: false`）      | `subagent-start` の難易度表で決める（迷ったら一段低く）                    |

### 自分が Codex 側のとき

| 役割                     | モデル                                                                                                                         | 推論レベル                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 自分（計画・評価・統合） | 現在のセッション                                                                                                               | —                                                                 |
| セカンドオピニオン       | 別ベンダーで自分と同格: Claude Opus 5.5（T3 `delegate_task`, `providerInstanceId: "claudeAgent"`, `model: "claude-opus-5-5"`） | 自分と同じレベル（`effort`）。自分のレベルが分からなければ `high` |
| 実装者                   | 原則として同ベンダーの最下位モデル: GPT-6.1 Sol（T3 `delegate_task`）                                                          | `subagent-start` の難易度表で決める（迷ったら一段低く）           |

- 実装が最下位モデルには困難だと判断した場合は、同ベンダーで一つ上のモデルを指定する。利用可能なモデル ID は起動前に確認する。
- 指定モデルが使えないときは勝手に切り替えず、ユーザーに伝えて止まる。

## ループ

1. **自己評価**: ゴール条件（原文）を項目に分け、各項目について証拠（差分、実行したチェックとその結果）で達成を確かめる。未実行のチェックは未達として扱う。
   - 未達がある → 4 へ。
   - すべて達成 → 2 へ。
2. **セカンドオピニオン依頼**: 毎回新しい `delegate_task` で別ベンダーのモデルを起動する（`t3_thread_send` での再利用はしない）。ブリーフに含めるもの:
   - ゴール条件（原文そのまま）
   - 自己評価の結果: 項目ごとの判定と根拠
   - 現状の証拠: 変更差分（`git diff` / コミット範囲）、実行したチェックとその結果
   - 前回のセカンドオピニオンで退けた指摘があれば、その理由
   - 依頼内容: 自己評価をうのみにせず、リポジトリを自分で読み、必要ならテストを実行して達成可否を判定すること。出力は `VERDICT: PASS` か `VERDICT: FAIL` で始め、FAIL なら未達項目を「何が・どこで・どう確認すれば達成か」の形で列挙する。
3. **判定**:
   - **PASS** → ユーザーに自己評価とセカンドオピニオンの判定・根拠を報告して終了。
   - **FAIL** → 指摘を自分で検証し、妥当なものだけを未達項目にする（不当な指摘は理由を控えて次回ブリーフに書く）。妥当な指摘がなければ、退けた理由を添えて 2 をやり直す。
4. **実装**: 未達項目ごとに実装者を起動する。ブリーフには対象ファイル、期待する挙動、実行すべきチェックを書く。独立した項目は並列で起動してよい。
5. **統合と検証**: 自分で差分を確認し、AGENTS.md のチェック（typecheck / lint / テスト / build / 必要な E2E）を通す。
6. 1 に戻る。

- セカンドオピニオンの依頼は上限 5 回。超えたら、残った指摘と止まっている理由をユーザーに報告して判断を仰ぐ。
- コミット・push は AGENTS.md の方針どおり、検証済みの単位で行う。大きな変更では上記の PR 手順に従う。
