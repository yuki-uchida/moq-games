# /goal 運用ルール

`/goal` でゴールが有効な間はこの手順で進める。組み込みのゴール評価（会話だけを見る Claude 側の判定）とは別に、**別ベンダーのレビュー合格**を完了条件に加える。サブエージェントの起動方法・報告形式は `agent-start` スキルに従う（このスキルはユーザー指定なので、モデル選択は下記が優先）。

## 役割

| 役割                     | モデル                                                                                                               | 推論レベル                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 自分（計画・統合・検証） | 現在のセッション                                                                                                     | —                                                                          |
| 評価者                   | 別ベンダーで自分と同格: GPT-6.1 Terra（T3 `delegate_task`, `providerInstanceId: "codex"`, `model: "gpt-6.1-terra"`） | 自分と同じレベル（`reasoningEffort`）。自分のレベルが分からなければ `high` |
| 実装者                   | 同ベンダーの下位モデル: Claude Sonnet 5.5（Agent ツール `model: "sonnet"`, `run_in_background: false`）              | `agent-start` の難易度表で決める（迷ったら一段低く）                       |

- 自分が Codex/GPT 側で動いている場合は逆にする: 評価者 = Claude Opus 5.5（同レベル）、実装者 = 同ベンダーの下位モデル。
- 指定モデルが使えないときは勝手に切り替えず、ユーザーに伝えて止まる。

## ループ

1. **評価依頼**: 毎回新しい `delegate_task` で評価者を起動する（`t3_thread_send` での再利用はしない）。ブリーフに含めるもの:
   - ゴール条件（原文そのまま）
   - 現状の証拠: 変更差分（`git diff` / コミット範囲）、実行したチェックとその結果、未実行のチェック
   - 依頼内容: リポジトリを自分で読み、必要ならテストを実行して達成可否を判定すること。出力は `VERDICT: PASS` か `VERDICT: FAIL` で始め、FAIL なら未達項目を「何が・どこで・どう確認すれば達成か」の形で列挙する。
2. **PASS** → ユーザーに評価結果の要約を伝えて終了（組み込みのゴール評価も満たすよう、最終報告に評価者の判定と根拠を書く）。
3. **FAIL** → 指摘を自分で検証し、妥当なものだけを実装項目に分解する（不当な指摘は理由を添えて次回ブリーフに書く）。
4. **実装**: 項目ごとに実装者を起動する。ブリーフには対象ファイル、期待する挙動、実行すべきチェックを書く。独立した項目は並列で起動してよい。
5. **統合と検証**: 自分で差分を確認し、AGENTS.md のチェック（typecheck / lint / テスト / build / 必要な E2E）を通す。
6. 1 に戻る。

- 上限 5 ラウンド。超えたら、残った指摘と止まっている理由をユーザーに報告して判断を仰ぐ。
- コミット・push は AGENTS.md の方針どおり、検証済みの単位で行う。
