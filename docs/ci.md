# CIの実行範囲

`.github/workflows/check.yml` は `main` へのpush時だけ実行する。PRの作成・更新や作業ブランチへのpushでは実行しない。

- Markdown、`.claude/`、`.agents/`、`.codex/` だけの変更ではワークフローを起動しない。`docs/` はタワーのテストが読む `docs/animation-repair-audit.json` だけを判定し、ほかは検証しない。
- `main` へのpush直前と直後のコミットを比較し、push内の全コミットの変更を判定する。削除・移動前のパスも判定に含める。
- タワーのテストファイル（Pagesのブラウザテスト・ユニットテスト・Node契約テスト）だけの変更では、変更したテストファイルだけを実行し、公開はしない。テスト用の共通ヘルパーやゲーム本体・素材を含む変更、およびテストファイルの削除・移動を含む変更（`git diff --diff-filter=D` で判定）では、存在しないファイルを指定せずタワー全体を検証する。
- ゲーム固有の変更では、そのゲームの既存ユニットテスト・契約テストを実行し、変更していないゲームの検証は実行しない。タワーの変更では既存のPagesブラウザテスト、予測検証、オフラインbotテストも実行する。タワーの変更ではPagesブラウザテストを18分割で実行する（全体検証は16分割）。ゲーム専用のVite・Playwright設定や素材加工スクリプトもそのゲームの変更として扱う。
- 別のゲームのコードや素材を使うゲームは、使われる側の変更でも検証する。Ember Gridはタワーの `src/game/`・`src/progression/`・`src/rendering/` と `public/tower-defense-art/`・実行時に取得する `public/tower-defense-sfx/`、人生サバイバーはウサギの `src/network.ts`、トップページはタワーのモデルビューワーとポートレート画像を使う。`tests/ci-scope.test.mjs` が全ゲームのimportをたどり、またソース中の `BASE_URL` から作る素材URLを走査して、使う側を選ばないファイルや他ゲームの `public/` ディレクトリがあれば失敗する。
- Ember Gridの変更では専用の型チェックと既存のPagesブラウザテストも実行する。
- トップページのブラウザテストはラビッターズ・レーンバトル・夜の屋敷も起動するため、これらのゲームの変更ではトップページのカタログテストとブラウザテストも選ぶ（Ember Grid・人生サバイバー・マモノ陣形では選ばない）。
- トップページの変更ではカタログテストとトップページのブラウザテストだけを選ぶ。
- botだけ・デバッグツールだけの変更では専用の検証だけを実行し、ゲームの検証・Pages公開は実行しない。
- テストの選び方・配分だけを決めるファイル（`scripts/ci-scope.mjs`、`tests/ci-scope.test.mjs`、`scripts/ci-pages-shard.mjs`、`scripts/ci-pages-weights.json`、`scripts/vitest-unit-weights.json`、描画ベンチマークのworkflow）だけの変更では、CIの契約テストだけを実行し、ゲームの検証・Pages公開は実行しない。
- Pagesのビルドは変更判定と並行して始め、公開対象がない変更（botだけ・デバッグツールだけ・CIの選び方だけなど）では公開しない。
- 共通コード（`lib/moqt/`、`utils/`、`examples/games/shared/`）の変更では、変更したファイルを使うゲームだけを検証する。使うゲームは `scripts/ci-scope.mjs` の表で決め、表にない新しいファイルは全体を検証する。
- `check.yml` の変更では、前後のワークフローを比べて定義が変わったジョブだけを実行し、CIの契約テストも実行する。ワークフローの先頭部分（トリガーなど）、`changes`、`deploy`、判定に載っていないジョブを変えたときは全体を検証する。
- 依存関係、Chromium導入、テストランナー設定、未分類ファイルの変更では全体を検証する。

型チェック・lintは共通の既存コマンドを使う。公開対象が変わる場合のPagesビルドはサイト全体で行い、出力とライセンス通知の検証を維持する。選択された検証の失敗・キャンセル時には公開しない。変更範囲に含まれない検証のskipは公開を妨げない。

実行範囲の定義は `scripts/ci-scope.mjs`。変更時は次で判定とワークフローの契約を検証する。

```sh
node --test tests/ci-scope.test.mjs
```
